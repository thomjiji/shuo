# shuo

> 本项目仅供我个人使用，它的生命周期直到豆包输入法推出 Windows 版的那一天为止。因为那时候我就跑去用豆包输入法 Windows 版了。

Windows 原生 WinUI 3 听写应用，支持本地模型和豆包云端流式识别。按全局快捷键开始录音，再按一次停止，最终文本会粘贴到原前台输入框。

在另一台 Windows PC 上运行，请参阅[安装指南](docs/setup.md)。

## 使用

1. 启动应用。左侧导航分为“常规”“转录服务”“转录历史”和“文本整理”，窄窗口下收起为图标栏。
2. 如需修改快捷键，在“常规”页点击“录音触发快捷键”右侧的铅笔图标，在卡片内按下新组合键并保存。默认 `Ctrl+Alt+\`；清除会禁用全局快捷键。
3. 在普通权限应用的输入框中按一次快捷键开始录音，再按一次停止。
4. 转写完成后，文本会自动粘贴。

设置窗口打开时会显示在任务栏，可右键任务栏图标选择“固定到任务栏”。以后点击固定图标即可启动应用；如果应用已在运行，会打开已有的设置窗口。固定后请保持 EXE 的位置不变，更新时替换同一路径的文件。

关闭主窗口后，应用继续在系统托盘运行，不占用任务栏。点击托盘图标可打开设置；右键图标可选择“打开设置”或“退出”。需要完全停止应用时，选择“退出”。

在“转录服务”中选择“豆包云端”，填写火山引擎语音控制台的 API Key，再点击“保存并测试”。默认使用流式语音识别 2.0 小时版；旧版 App ID、Access Token 和资源 ID 可在展开项中配置。录音时音频会上传，屏幕底部的单行字幕条随文字长度展开，到达最大宽度后保持不变；新文字出现时平滑左移，让最新内容保持在右侧，没有新文字时停住。左侧蓝点的波纹随麦克风音量变化，粘贴完成后字幕条收起。字幕条自动跟随系统亮暗主题，无需重启。需要联网并按服务用量计费，凭据保存在 Windows 凭据管理器中。选择“本地模型”并保存即可切回本地听写。

在“转录服务”页选择“本地模型”并保存后，可切换同一目录中已下载的 GGUF 模型，文件名包含量化版本。通过 pi-transcribe 下载新模型后，点击旁边的刷新按钮。选择加载成功后自动保存；录音、转录和模型加载期间不能切换，失败时保留原选择。

“文本整理”页提供两个独立开关，默认关闭，自动保存并从下一次听写生效：

- “去除口水词”：清除停顿中独立出现的“嗯、呃”，并整理相邻分隔符。保留单独回应的“嗯”、正常语气和引号内容；边界不明确时保留原文。
- “去掉末尾句号”：去掉整次输入最后的句号，长段落也适用。保留句中标点、问号、感叹号、省略号，以及常见英文缩写等有歧义的句点。

文本整理在本地完成，不需要额外模型或 API。

“转录历史”按新到旧显示本地模型和豆包云端完成的转录，保存的是经过排版和文本整理后的最终文字，可选择文字或点击“复制”再次使用。搜索框会在全部记录的文字、日期和服务名称中查找，不区分英文大小写。每次先显示 50 条匹配记录，点击“加载更多”继续查看。记录在粘贴前保存，因此粘贴失败时仍可找回；空结果和未完成的实时文字不会入库。

历史从此版本开始记录，保存在当前电脑的 `%LOCALAPPDATA%\Shuo\history.jsonl`，重启和替换 EXE 后保留，不会自动清理或跨电脑同步。文件包含转录文字、完成时间和具体模型名称：本地模型记录文件名（含量化版本），豆包记录识别模型版本和资源 ID，不保存音频。旧记录没有保存具体模型，仍保留原来的服务名称。点击“打开历史文件”可选择 VS Code 等编辑器打开 JSONL 文件，新增记录直接保留中文；读取历史时会将旧记录的 Unicode 转义转换为中文，并在同目录保留带唯一后缀的 `.bak` 原文件备份。点击“导出并打开文本”会将全部记录（包括旧版转义记录）写入同目录的 `history.txt`，方便阅读和搜索；每次导出都会更新 TXT 文件，窗口中的搜索条件不影响导出范围。备份时复制 `history.jsonl`。

本地模型在停止录音后转写。豆包的实时文字可能修正，只有最终结果会粘贴；连接中断或超时时会提示失败。普通权限应用不能向管理员权限目标粘贴文本。

## 配置

新安装的配置位于 `%LOCALAPPDATA%\Shuo\settings.json`。如果新文件不存在，应用会继续使用已有的 `%LOCALAPPDATA%\WindowsDictation\settings.json`，保留原有快捷键和偏好。两者都不存在时，首次启动服务会优先从 `~/.pi/agent/pi-transcribe.json` 导入配置；没有可导入文件时自动创建默认配置，可直接在界面填写豆包 API Key。

GGUF 模型不包含在 EXE 中。使用本地模型时，按[安装指南](docs/setup.md#3-创建配置)填写模型路径。

## 开发

需要 Windows、.NET SDK 10、Node.js 22+ 和本地 GGUF 模型。

```powershell
npm ci
dotnet run --project src/Shuo/Shuo.csproj
```

项目结构和进程协议见[开发说明](docs/development.md)。

## 发布

按[安装指南](docs/setup.md#1-在构建电脑生成一个-exe)构建 x64 单文件 EXE。
